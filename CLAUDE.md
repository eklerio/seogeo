## What's built
- First-time **destination setup form** at `/` (SEOGEO Solver): Block A (website URL, company name, AI-suggested alias chips, country, language), Block B (editable AI summary), Block C (editable competitors), Block D (editable tracking questions). Edge cases handled: invalid URL, unreachable site (manual fallback), required-field blocking. **Onboarding is 3 clear steps (Elen's ask 2026-07-08)** with a step indicator up top (`Steps` component: Website · Details · Connect + "Step N of 3"). `Onboarding.tsx` state `step: "url" | "details" | "connect"`. **Step 1 (url):** just one URL input + a **Go** button (enabled only when `isValidUrl`); Go runs `scanSite(url)` (exported from `DestinationForm.tsx` — reads the site, then parallel-fetches industry phrases + aliases, returns a full `DestinationInput`) while showing `ScanLoader` (spinner + rotating entertaining messages: "Searching your website…", "Spotting your competitors…", "Sipping coffee…", …). On scan failure it still advances with a url-only manual fallback. **Step 2 (details):** the full `DestinationForm` **with `hideUrl` (the URL field + auto-scan are suppressed since we already scanned)**, seeded via `initial={scanData}`, submit label "Next: connect your data →"; on save (`onDone`) → step 3. **Step 3 (connect, optional):** renders `ConnectionCards` (exported from `Connections.tsx`, self-fetching wrapper around the private Bing/Google cards, also used inside the Connections modal) + "Open my board →" / "Skip for now" (both → `/workspace`). Google sign-in from onboarding round-trips correctly: the OAuth **`?back=` return path** — `/api/google/auth?back=<path>` stores it in a `google_oauth_back` cookie (must start with `/`, else `/workspace`), the callback redirects to it with `?google=ok|error&reason=…`; onboarding passes `back=/?connect=1`, and `app/page.tsx` maps `?connect=1` (+ `google`/`reason` params) to `initialStep="connect"` + `googleResult`, skipping the workspace redirect.

- **Sortable tables — shared convention (`components/Workspace.tsx`):** every table/list (Questions we track, Google rankings, Competitors, Action Plan) sorts via one shared model — `useTableSort()` (state + asc⇄desc toggle on repeat click), `sortRows(rows, sort, accessors)` (returns a sorted copy; **blank/null values always sink to the bottom regardless of direction**), and `<SortLabel>` headers (caret: ↕ idle, ▲/▼ active). **The first/title column is never sortable** (Question text, Search phrase, Phrase to target, Company name); every other column is. **Build new tables the same way:** give each non-title column a `key` + accessor, render its header with `<SortLabel>`, map over the `sortRows(...)` output. Because rows reorder on sort, **row actions (remove) key off identity, not array index** (e.g. `removeQuestion(text)` / `removeKeyword(kw)`, not `(idx)`). Action Plan + Competitors default-sort by their impact metric (`searchVolume` / `estVisits` desc).
- **Two tracked lists per destination:** `questions` (10–15 conversational, drive AI Share of Voice) and `keywords` (10–15 short Google phrases like "web3 security audit", drive Avg Google Rank). Both AI-suggested on site scan, editable in the form.
- **Weekly report engine** (`lib/dataforseo.ts` + `lib/report.ts`, `POST/GET /api/report`): each run is a snapshot in `data/reports.json`; Overview compares latest two ("this week vs last"). AI Share of Voice = company-vs-competitor brand mentions counted in live ChatGPT + Gemini answers (DataForSEO LLM, avg of engines), over the questions. Avg Google Rank = company's position for each short keyword via SERP API (depth 100), shows "X of N ranked". **Both AI engines' answers are cached weekly** (`data/llm-cache.json`, keyed `destId:engine`, mirrors the competitor-intel cache) — they're the priciest lines (~$0.50 Gemini + ~$0.18 ChatGPT). Re-runs within a week reuse them; scoring stays live so company/competitor name edits are still reflected. Refetches when a week passes or the question list changes. **Run anytime:** the button is never gated — a re-run always refreshes Google rankings (SERP + keyword data) while reusing the cached AI + competitor data. **Per-run cost:** `runReport` records the data-spend delta it added onto `snapshot.costUsd`, shown in the Overview run bar ("this run cost $X"). Rough costs (Hexens-size list): **first run of the week ~$1.18** (incl. $0.09 Bing volumes, cached weekly), **same-week re-run ~$0.16** (Google rank checks + keyword data only). **Up-front estimate:** `estimateNextRun(dest)` (exposed at `POST /api/report/estimate`, returns `{totalUsd, firstOfWeek, perQuestionUsd, perKeywordUsd}`) prices the next run from `UNIT_COST` per-call averages × counts, accounting for which caches are still warm — the **Run report** button shows it ("Run report: $0.16") and re-prices whenever the tracked lists change or a run finishes.
